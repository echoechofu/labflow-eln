# Protocol 可视化编排第一步验收

2026-09-13

实现范围：新增和版本编辑共用 ProtocolComposer。模块库支持正文段落、文字、数字、下拉选项；点击或指针拖入配置区。正文段落与字段分别排序，提供上下移动按钮。中文下拉选择显示条件，正文通过字段按钮插入占位符，右侧提供试填和正文效果。来源结构字段继续沿用既有保护规则。

保存契约仍是 fields、template、templateVariants；段落以空行连接为文本，不新增领域实体。重新打开时按空行划分正文段落。预览中的试填不写入请求；样本和布局仅提示在实际 Record 配置。此阶段不开放执行规则的任意组合。

验收记录：

- 隔离浏览器中实际拖入下拉模块成功；实际拖动正文与字段后顺序改变，提交参数保留对应顺序。
- 选择“处理类型 = 处理”后浓度出现；未满足时隐藏；试填 2.5 后正文即时渲染。
- 段落中输入连续空行并继续输入，内容与焦点正常，提交文本保留空行。
- 细胞传代“悬浮”正文修改后切换“贴壁”，贴壁正文保持原文；提交包含两个独立变体及原来源 ID。
- 检查三栏布局，修复控件宽度溢出；模块库与预览滚动时保持可见。
- 27 项前端测试、14 项 Rust Protocol service 测试、lint、TypeScript/Vite 构建通过。

浏览器保存由 tests/protocol-editor-fixture.tsx 内存模拟并展示提交 JSON；持久化规则由服务回归测试覆盖，未写入用户实验数据。未进行 Windows 安装包验收或发布。

## 后续反馈修正

- 字段卡片顶部增加红色“删除字段”；来源保护字段明确显示不可删除。隔离页面实测新增后删除，提交 fields 为空。
- 从头创建、多个输出、按条件分配时，将孔板映射从 Sample Flow 步骤移到编排区“容器与位置”，模块库可点击或拖入孔板位置。独立培养皿等容器沿用不映射孔位的分组模式，不创建皿编号。
- 隔离页面确认孔板选项提交 plateMapping=true，同时原输出类型 CDNA 保持不变。lint、构建、diff 检查通过。

## 2026-09-14 调整

- 来源执行规则依赖的 Record placeholder 改为静态 `{{key}}` 展示，不再呈现可编辑输入框；来源字段仍可修改面向用户的标签和默认值。
- Protocol 弹窗改为固定页头、独立滚动正文和固定页脚，提交按钮取消阴影并限制在页脚布局内，解决窄高度窗口中的重叠。
- 条件容器增加 `dish` 模式。创建 Record 时每个条件组可填写实验条件、浓度、处理时间、处理方法和皿数；服务按顺序生成“皿 01、皿 02……”并在输出 Sample metadata 保存 `container_type=DISH`、`container_position` 与 `condition_method`。
- 兼容旧 `plateMapping`，新配置同时保存 `conditionAllocation.containerMode`；Desktop 与 MCP 继续进入同一 Protocol service。
- 只读 placeholder 和页脚经隔离浏览器截图检查；培养皿编号、方法摘要与 service schema 有专用 Rust 测试。前端构建、lint、Rust 全量基准和 diff 检查通过。
